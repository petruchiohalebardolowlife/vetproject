# Промпт v3: сайт-визитка ветеринара (Кирилл Сачков) — выразительный дизайн с анимациями

> Это третья версия промпта. Функциональность, контент и структура те же, что в `PROMPT.md`; **визуальная часть заменена целиком** (раздел «Дизайн и анимации»). Требования к дизайну из `PROMPT.md` (плоский стиль без градиентов, «один шрифт», «версия 2») **больше не действуют**. Цветовая гамма заказчика сохраняется.

## Роль и задача

Ты — senior frontend-разработчик. Создай в текущей (пустой) директории сайт-визитку ветеринара **Кирилла Сачкова** (бренд в соцсетях: «Ветеринар от Бога»). Сайт полностью статический: **никакой серверной логики, API, БД и аутентификации**. Проект будет демонстрироваться заказчику (деплой на Vercel), позже переедет на собственные мощности, поэтому сборка должна давать обычную статику (`vite build` → `dist/`), без привязки к Vercel-специфике.

Перед началом работы изучи макет (описан ниже), составь краткий план и только потом пиши код. Если что-то в ТЗ противоречиво или непонятно — задай вопрос, не додумывай молча; мелкие решения принимай сам и перечисли их в финальном отчёте.

## Технологический стек (обязательно)

- **React** (актуальная стабильная версия, функциональные компоненты и хуки)
- **TypeScript** (`strict: true`, никаких `any` без веской причины)
- **Vite** (шаблон `react-ts`)
- Менеджер пакетов: npm (если не указано иное)
- Стили: обычный CSS с переменными (CSS custom properties). Тяжёлые UI-фреймворки и библиотеки анимаций (framer-motion, GSAP и т.п.) **не нужны**: все анимации делаются на CSS, `IntersectionObserver` и небольших хуках.
- Перед использованием API библиотек сверяйся с актуальной документацией (версии React/Vite меняются), не полагайся на память.
- Шрифты — только самохостинг через npm (`@fontsource-variable/inter` для текста и `@fontsource-variable/noto-serif` (курсивное начертание `wght-italic.css`) для заголовков, оба с кириллицей), без запросов к внешним серверам.
- Никаких лишних зависимостей. Для формы библиотеки (react-hook-form и т.п.) не нужны — достаточно контролируемых компонентов.

2. **Hero-блок (главный экран).**

   - Справа — крупный заголовок **«Кирилл Сачков»**, под ним **описание** (пока заглушка-текст). Весь правый блок (заголовок, описание, кнопки) **выровнен по центру** по горизонтали внутри свободной области справа от фото, текст центрирован (`text-align: center`).
3. **Блок CTA.** Две кнопки в ряд под описанием, выровнены по центру свободной области справа от фото: слева «Оставить заявку», справа «Записаться на приём».

4. **Блок соцсетей.** Ряд карточек, каждая — подпись + кликабельная картинка (иконка/превью) под ней. **Порядок (по решению заказчика): Instagram, Telegram, VK, TikTok, YouTube** (VK добавлен по договорённости, в скетче его нет). На десктопе — ряд из 5 карточек; на планшете и телефоне (≤ 1000 px) — горизонтальная лента со свайпом (см. «Карточки соцсетей»), а не сетка с переносами. Видимого заголовка над блоком (вроде «Я в соцсетях») **нет**; для доступности у секции задан `aria-label="Социальные сети"`.
5. **Футер.** Текст «Права и т.д.» — сделай стандартный футер: © 2026 Кирилл Сачков, «Все права защищены». Позже заказчик уточнит текст.

На десктопе — как в скетче. Обязательно адаптивная вёрстка (mobile-first): на узких экранах hero складывается в колонку (фото сверху), навигация сворачивается в бургер-меню, соцсети переносятся сеткой 2 в ряд.

## Навигация и структура страницы

Сайт — **одна длинная главная страница**: разделы идут друг за другом, переход по меню — плавная прокрутка к якорю (раньше разделы были отдельными страницами, теперь нет; требование «этих блоков не должно быть на главной» из `PROMPT.md` **отменено**).

Порядок блоков на главной (`/`): Hero → бегущая строка → карточки соцсетей → **О враче** (`#about`) → **Услуги** (`#services`) → **Блог** (`#blog`) → **Сотрудничество** (`#cooperation`) → футер.

- Пункты меню — обычные ссылки `href="/#id"` (работают и со страницы 404, и при прямом открытии `/#services`). `html { scroll-behavior: smooth }` только при `prefers-reduced-motion: no-preference`; у секций `scroll-margin-top`, чтобы заголовок не прятался под плавающей шапкой.
- **Scroll-spy:** меню подсвечивает раздел, который сейчас у линии ~40 % высоты экрана (хук `useActiveSection`, считает `getBoundingClientRect` в `requestAnimationFrame`); у активной ссылки `aria-current="true"`. Пока на экране hero/соцсети — активного пункта нет.
- При открытии адреса с `#якорем` страница после рендера прокручивается к нужной секции; без якоря — наверх.
- Клик по бренд-метке на главной плавно возвращает наверх и убирает `#якорь` из адреса.
- `react-router` остаётся только для маршрута `*` (страница «Страница не найдена» со ссылкой «← На главную») и общего layout. Отдельных страниц `/about`, `/services`, `/blog`, `/cooperation` **нет**.
- Шапка, футер, форма записи и уведомление «Готово» — в общем layout; форма открывается с любого места.
- `vercel.json` с rewrite на `/index.html` оставь (нужен для страницы 404 и прямых ссылок); в README отметь fallback для собственного сервера.

## Форма записи на приём

Открывается как **модальное окно** по клику на любую из двух кнопок «Записаться на приём»: в шапке и в CTA-блоке под описанием. Кнопка «Оставить заявку» форму **не** открывает (пока ничего не делает).

Поля:
| Поле | Тип | Правила |
|---|---|---|
| Имя | text | обязательное, не пустое после trim |
| Телефон | tel | обязательное, валидация формата телефона РФ (допускай +7/8, пробелы, скобки, дефисы; нужно 11 цифр), по возможности маска ввода без внешних библиотек |
| Комментарий | textarea | необязательное (например, вид животного, суть проблемы) |
| Согласие на обработку персональных данных | checkbox | обязательное, подпись вроде «Я подтверждаю, что ознакомлен(а) с политикой обработки персональных данных и согласен(на) на обработку моих данных» (ссылка-заглушка на политику) |

Кнопка «Отправить».

Поведение:
- При невалидных данных — показать понятные сообщения об ошибках под полями, форму не отправлять. Кнопка «Отправить» может быть неактивной, пока нет согласия.
- При валидных данных клик по «Отправить» **ничего никуда не отправляет**: форма закрывается и показывается уведомление **«Готово»** (toast или короткое сообщение, автоскрытие через ~3 секунды). Данные можно только вывести в `console.log` (оставь комментарий `// TODO: заменить на реальную отправку`), отправку вынеси в отдельную функцию-заглушку, чтобы потом подменить её без переписывания UI.
- После закрытия форма сбрасывается.
- Закрытие: крестик, клик по оверлею, клавиша Esc.

Доступность модалки: `role="dialog"`, `aria-modal`, фокус уходит в модалку и возвращается на кнопку-триггер после закрытия, фокус не выходит за пределы модалки (focus trap), блокировка прокрутки фона. Можно использовать нативный `<dialog>`.

## Дизайн и анимации

Цветовых гамм **две**, между ними есть временный тумблер (заказчик выберет одну, вторую потом удалим). По умолчанию — голубая.

**Гамма 1 — голубая (по умолчанию, `:root`):**
- **Фон:** `#D8EBF2` — нейтральный пыльно-голубой. **Акцент:** `#87CEEB` («sky blue»). Производные: тёмный сине-графитовый `#1F3A4D` для текста и тёмных блоков, приглушённый `#4A6578`, более тёмный акцент `#2F6F8F` для текста, иконок, рамок и focus, белый для карточек.

**Гамма 2 — оливково-розовая (`html[data-theme='olive']`), цвета из дизайн-проекта «питушочки»:**
- Оливка тень `#5C6B4A` (приглушённый текст), строчка `#B8BCA0` (от неё — светлый фон страницы `#E6E8DE`), роза корпус `#DBADB2` (акцент), роза акцент `#B87A84` (декор: лапки, пунктиры).
- Производные: оливка корпус `#3D4A32` (текст и тёмные блоки), затемнённая роза `#8F5560` (ссылки, рамки, focus — контраст ≥ 4.5:1), поверхность `#FBF9F4`, границы полей `#6F7A5A`, плейсхолдер `#CDD1BB`. Цвет «роза акцент» `#B87A84` на светлом фоне даёт только ~2,8:1, поэтому для текста и рамок он не используется.

**Реализация:** все цвета — CSS-переменные в `:root`; вторая гамма переопределяет их в `:root[data-theme='olive']`. Прозрачные варианты берутся из RGB-троек (`--accent-rgb`, `--text-rgb`, `--on-dark-rgb`), жёстко прописанных цветов в компонентах быть не должно. **Тумблер:** компонент `PaletteToggle` (фиксированная «таблетка» слева внизу с двумя круглыми образцами, `aria-pressed`), выбор сохраняется в `localStorage` (с `try/catch`) и применяется inline-скриптом в `index.html` до отрисовки (без вспышки), обновляет `meta[name=theme-color]`. Компонент помечен как временный (комментарий в файле), чтобы его легко удалить.

Цель: сайт должен выглядеть современно, живо и дорого, но оставаться лёгким и доверительным («ветеринарная» тематика: лапки, мягкие формы). Допустимы мягкие размытые пятна и тонкие световые блики из палитры; никаких кричащих, неоновых или посторонних цветов.

### Типографика
- Заголовки (имя врача, заголовки разделов и страницы 404, бренд-метка, бегущая строка, бейдж, заголовок формы) — **Noto Serif Italic** (шрифт логотипа «питушочки» из дизайн-проекта заказчика; курсив обязателен, `font-style: italic`), вес 600–700, крупные. Основной текст, кнопки, меню — **Inter**. Шрифты подключаются локально, внешние запросы запрещены.
- Размеры заголовков через `clamp()`.

### Фон
- Фиксированные размытые «пятна» (`filter: blur`) цветов акцента и белого, медленно дрейфуют (`@keyframes drift`) и слегка смещаются при прокрутке (параллакс). Компонент `Decor`, `aria-hidden`, `pointer-events: none`, `z-index: -1`.

### Шапка
- Плавающая «таблетка» (`border-radius: 999px`), полупрозрачный белый фон с `backdrop-filter: blur`, `position: sticky`. Слева **бренд-метка**, затем меню, справа кнопка «Записаться на приём».
- **Бренд-метка:** круглый акцентный значок с лапкой и подпись «Кирилл Сачков» (Noto Serif Italic, в две строки); это ссылка на главную (`aria-label` «Кирилл Сачков — на главную»), при hover значок поворачивается и увеличивается. Подпись скрывается на ширине ≤ 1100 px.
- **Меню со «скользящей» подсветкой:** одна общая «таблетка» цвета акцента плавно переезжает (`transform` + `width`, ~0.4 с) к пункту под курсором или в фокусе и возвращается к активной странице, когда курсор уходит. На главной (активного пункта нет) подсветка скрыта, пока нет hover. Активный пункт — жирный. Положение считается по `offsetLeft/offsetWidth` и записывается в CSS-переменные напрямую в DOM (без React-состояния); пересчёт при смене маршрута и `resize`. Работает и с клавиатуры (focus).
- **Кнопка «Записаться на приём»:** тёмная (`#1F3A4D`, белый текст) со стрелкой; при hover заливается акцентом и стрелка сдвигается.
- При прокрутке шапка становится компактнее и плотнее (класс `is-scrolled` на `<html>`), внизу тонкая **линия прогресса прокрутки** (`transform: scaleX(var(--scroll-progress))`).
- **Бургер-меню включается на ширине ≤ 900 px** (на 768 px полное меню вместе с брендом и кнопкой не помещается: пункты переносятся на две строки, кнопка обрезается). На таких ширинах: круглый бургер, бренд-метка (без подписи) и кнопка записи в ряд; меню открывается карточкой под панелью с анимацией, скользящей подсветки там нет (активный пункт подсвечен фоном).

### Hero
- Фото врача в форме **арки** (`border-radius: 240px 240px 32px 32px`), позади — повёрнутая плашка цвета акцента той же формы. На устройствах с мышью (`@media (hover: hover) and (pointer: fine)`) фото и плашка двигаются при прокрутке (параллакс); **на телефонах параллакса нет**. Появление фото — через `opacity` и `transform`, **без `clip-path`**: на iPhone (Safari) комбинация `clip-path` + `translate` + скруглённый `overflow: hidden` давала горизонтальную светлую «полоску» поперёк фото.
- **Бейдж:** белый круг (150 px, на мобильных 118 px) с медленно вращающейся пунктирной окантовкой и статичным текстом по центру: «Более» / крупно «15 лет» / «заботы о питомцах» (Noto Serif Italic; текст лежит в `doctor.badge`). Расположен **ниже, на нижнем правом углу фото** (`right: -16px; bottom: -30px`), чтобы не закрывать лица на фото. Появляется с задержкой (`badge-in`).
- Декоративные отпечатки лап: приглушённые, медленно «парят» (`@keyframes float`).
- Правый блок отцентрован: имя из двух слов, каждое на своей строке. **Появление при загрузке:** слова выезжают снизу из-под маски (`overflow: hidden`, `@keyframes word-up`), затем под фамилией «вырастает» маркер-подчёркивание цвета акцента (`scaleX`). Описание и кнопки плавно выплывают с задержкой. Фото плавно появляется снизу.
- Кнопки: «Оставить заявку» (залита акцентом, при hover по ней пробегает блик) и «Записаться на приём» (контурная, со стрелкой, которая сдвигается при hover). Подробности поведения кнопок — в разделе «Макет».

### Бегущая строка
- Между hero и соцсетями — наклонная (−1,5°) тёмная полоса с бесконечной прокруткой названий соцсетей и лапок (`@keyframes marquee`, цвет текста — акцент). Декоративная (`aria-hidden`), на hover останавливается.

### Карточки соцсетей
- Картинка на всю карточку (3:4, скругление 40 px), название сети — белая полупрозрачная «таблетка» слева сверху, справа снизу круглая стрелка ↗.

- Единственная отдельная страница — «Страница не найдена»: полупрозрачная белая карточка с крупным заголовком, плавающей лапкой и кнопкой «← На главную». Контент при смене маршрута плавно появляется (`page-in`, ключ — `pathname`).

### Форма записи
- Модальное окно (`<dialog>`) с большим скруглением; открытие — fade + подъём + лёгкий масштаб, оверлей с затемнением и `backdrop-filter: blur`. Кнопки — «таблетки».

### Реализация анимаций
- Положение прокрутки пишется хуком `useScrollEffects` в CSS-переменные на `<html>` (`--scroll-y`, `--scroll-progress`) через `requestAnimationFrame` и пассивный слушатель; параллакс делается свойством `translate: 0 calc(var(--scroll-y) * -0.05px)` (чтобы не конфликтовать с `transform` анимаций).
- Появление при прокрутке — компонент `Reveal` (`variant`: `up` | `fade` | `scale`, `delay`), срабатывает один раз.
- Анимируй только `transform` и `opacity` (и `translate`), не `width/height/top/left`, чтобы не было перерисовки раскладки. `will-change` — только у фоновых пятен.
- **`prefers-reduced-motion: reduce`:** отключить бесконечные и входные анимации (`animation-duration: 0.01ms`), показать всё без анимации, убрать параллакс (`translate: none`). Это обязательное требование.
- Анимации не должны мешать чтению и взаимодействию: нет автоплея со звуком, нет блокировки ввода, фокус и клавиатура работают как обычно. Отсутствие горизонтального скролла на мобильных (`overflow-x: clip` у `html` и hero).

### Доступность
- Контраст по WCAG AA (на акцентных заливках — тёмный текст, не белый). Видимый `:focus-visible` у всех интерактивных элементов.
- Декоративные элементы (пятна, лапки, бейдж, бегущая строка) скрыты от скринридеров (`aria-hidden`). У заголовка с разбитыми на слова анимируемыми элементами — `aria-label` с полным именем.
