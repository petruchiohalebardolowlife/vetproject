# Промпт: сайт-визитка ветеринара (Кирилл Сачков)

## Роль и задача

Ты — senior frontend-разработчик. Создай в текущей (пустой) директории сайт-визитку ветеринара **Кирилла Сачкова** (бренд в соцсетях: «Ветеринар от Бога»). Сайт полностью статический: **никакой серверной логики, API, БД и аутентификации**. Проект будет демонстрироваться заказчику (деплой на Vercel), позже переедет на собственные мощности, поэтому сборка должна давать обычную статику (`vite build` → `dist/`), без привязки к Vercel-специфике.

Перед началом работы изучи макет (описан ниже), составь краткий план и только потом пиши код. Если что-то в ТЗ противоречиво или непонятно — задай вопрос, не додумывай молча; мелкие решения принимай сам и перечисли их в финальном отчёте.

## Технологический стек (обязательно)

- **React** (актуальная стабильная версия, функциональные компоненты и хуки)
- **TypeScript** (`strict: true`, никаких `any` без веской причины)
- **Vite** (шаблон `react-ts`)
- Менеджер пакетов: npm (если не указано иное)
- Стили: CSS Modules или обычный CSS с переменными (CSS custom properties). Тяжёлые UI-фреймворки не нужны. Tailwind допустим только если обоснуешь выбор.
- Перед использованием API библиотек сверяйся с актуальной документацией (версии React/Vite меняются), не полагайся на память.
- Никаких лишних зависимостей. Для формы библиотеки (react-hook-form и т.п.) не нужны — достаточно контролируемых компонентов.

## Макет (скетч от руки, сверху вниз)

1. **Шапка (header)** (общая для всех страниц).
   - Слева — навигация: «О враче», «Услуги», «Блог», «Сотрудничество».
   - Справа — кнопка-рамка «Записаться на приём» (открывает форму записи).
2. **Hero-блок (главный экран).**
   - Слева — блок под **фото** (пока заглушка-плейсхолдер, в макете подписан «фото»).
   - Справа — крупный заголовок **«Кирилл Сачков»**, под ним **описание** (пока заглушка-текст). Весь правый блок (заголовок, описание, кнопки) **выровнен по центру** по горизонтали внутри свободной области справа от фото, текст центрирован (`text-align: center`).
3. **Блок CTA.** Две кнопки в ряд под описанием, выровнены по центру свободной области справа от фото: слева «Оставить заявку», справа «Записаться на приём».
   - «Записаться на приём» — **дублирует** кнопку из шапки (так задумано заказчиком) и открывает форму записи (см. ниже).
   - «Оставить заявку» — кликабельная кнопка (есть hover/focus-состояния), но **пока ничего не делает**: действие заказчик определит позже. Не привязывай к ней форму и не удаляй её; оставь `TODO`-комментарий.
   - На узких экранах кнопки переносятся в столбик.
4. **Блок соцсетей.** Ряд карточек, каждая — подпись + кликабельная картинка (иконка/превью) под ней. Порядок: YouTube, Instagram, Telegram, TikTok, **VK** (VK добавлен по договорённости, в скетче его нет). Видимого заголовка над блоком (вроде «Я в соцсетях») **нет**; для доступности у секции задан `aria-label="Социальные сети"`.
5. **Футер.** Текст «Права и т.д.» — сделай стандартный футер: © 2026 Кирилл Сачков, «Все права защищены». Позже заказчик уточнит текст.

На десктопе — как в скетче. Обязательно адаптивная вёрстка (mobile-first): на узких экранах hero складывается в колонку (фото сверху), навигация сворачивается в бургер-меню, соцсети переносятся сеткой 2 в ряд.

## Навигация и страницы

Пункты меню («О враче», «Услуги», «Блог», «Сотрудничество») — это **отдельные страницы** с маршрутами `/about`, `/services`, `/blog`, `/cooperation`. **На главной странице (`/`) этих блоков/секций быть не должно**: на ней только hero, кнопка «Оставить заявку» и соцсети. Клик по пункту меню обязательно должен что-то делать — переводить на соответствующую страницу (не якорь на той же странице: прежний вариант с якорями не работал, клик ничего не менял).

- Контента страниц пока нет: на каждой — заголовок, текст «Раздел в разработке» и ссылка «← На главную».
- Для роутинга используй `react-router` (declarative mode, `BrowserRouter`). Пункты меню — `NavLink` с подсветкой активной страницы (`aria-current="page"`).
- Шапка, футер, форма записи и уведомление «Готово» общие для всех страниц (layout-роут), форма открывается с любой страницы.
- При переходе между страницами прокрутка возвращается к началу. Неизвестный путь — страница «Страница не найдена».
- Для деплоя на Vercel добавь `vercel.json` с rewrite всех путей на `/index.html` (иначе прямые ссылки вида `/services` дадут 404). В README отметь, что на собственном сервере нужен такой же fallback на `index.html`.

## Форма записи на приём

Открывается как **модальное окно** по клику на любую из двух кнопок «Записаться на приём»: в шапке и в CTA-блоке под описанием. Кнопка «Оставить заявку» форму **не** открывает (пока ничего не делает).

Поля:
| Поле | Тип | Правила |
|---|---|---|
| Имя | text | обязательное, не пустое после trim |
| Телефон | tel | обязательное, валидация формата телефона РФ (допускай +7/8, пробелы, скобки, дефисы; нужно 11 цифр), по возможности маска ввода без внешних библиотек |
| Комментарий | textarea | необязательное (например, вид животного, суть проблемы) |
| Согласие на обработку персональных данных | checkbox | обязательное, подпись вроде «Я подтверждаю, что ознакомлен(а) с политикой обработки персональных данных и согласен(на) на обработку моих данных» (ссылка-заглушка на политику) |

Кнопка «Отправить».

Поведение:
- При невалидных данных — показать понятные сообщения об ошибках под полями, форму не отправлять. Кнопка «Отправить» может быть неактивной, пока нет согласия.
- При валидных данных клик по «Отправить» **ничего никуда не отправляет**: форма закрывается и показывается уведомление **«Готово»** (toast или короткое сообщение, автоскрытие через ~3 секунды). Данные можно только вывести в `console.log` (оставь комментарий `// TODO: заменить на реальную отправку`), отправку вынеси в отдельную функцию-заглушку, чтобы потом подменить её без переписывания UI.
- После закрытия форма сбрасывается.
- Закрытие: крестик, клик по оверлею, клавиша Esc.

Доступность модалки: `role="dialog"`, `aria-modal`, фокус уходит в модалку и возвращается на кнопку-триггер после закрытия, фокус не выходит за пределы модалки (focus trap), блокировка прокрутки фона. Можно использовать нативный `<dialog>`.

## Дизайн

Макет — только схема расположения. Цвета заданы заказчиком:

- **Фон:** `#D8EBF2` — нейтральный пыльно-голубой (по формулировке заказчика). Держи фон спокойным и однотонным, без градиентов и узоров.
- **Акцент (выделение объектов: кнопки, рамки, карточки, hover/focus):** `#87CEEB` («sky blue», подтверждено заказчиком; в исходной заметке был записан с кириллическими буквами, это опечатка).

Правила:
- Используй именно эти цвета как основу палитры и заведи их как CSS-переменные (`--color-bg`, `--color-accent` и т.д.). Дополнительные оттенки (hover, active, границы) выводи из них, а для текста подбери тёмный нейтральный цвет (например, тёмно-синий/графитовый).
- Оформление — по современным best practices: чистый плоский стиль, без кричащих градиентов, неоновых теней и тяжёлых декоративных бордеров. Допустимы аккуратные решения: тонкая граница, мягкая тень небольшой величины, скругления, лёгкий переход при hover. Градиент — только если он едва заметен и реально улучшает вид, по умолчанию его нет.
- **Контраст:** `#87CEEB` светлый, поэтому белый текст на нём не пройдёт WCAG AA. Используй на акцентных элементах тёмный текст и проверь соотношение контраста (≥ 4.5:1 для обычного текста, ≥ 3:1 для крупного и для границ интерактивных элементов). Если акцент как граница или фон не проходит контраст, добавь более тёмный вариант акцента для текста, иконок и focus-рамки и опиши это в отчёте.
- Видимое состояние `:focus-visible` у всех интерактивных элементов; не полагаться на один цвет для передачи смысла (ошибки формы — цвет + текст/иконка).
- Типографика: читаемая, кириллица обязательна, системный стек или один шрифт без внешних запросов; единая шкала размеров и отступов (CSS-переменные). Много воздуха, скруглённые карточки.
- Стиль общий: чистый, доверительный, «ветеринарный».

## Версия 2: визуальный язык (референс https://vet.city/)

Референс нужен только как источник приёмов, копировать его не нужно. Контент, разделы, тексты и палитра заказчика не меняются. Заимствованные приёмы:

- **Плавающая шапка-«таблетка»:** белая панель с полным скруглением (`border-radius: 999px`) и мягкой тенью, отступ от краёв страницы, `position: sticky`. Внутри слева меню, справа кнопка «Записаться на приём». Активный пункт меню — «таблетка» цвета акцента. На мобильных меню — круглая кнопка-бургер, список открывается карточкой под панелью.
- **Крупные «bento»-карточки:** hero, внутренние страницы и футер — белые блоки с большими скруглениями (40 px, на мобильных 28 px) на пыльно-голубом фоне, расстояние между блоками 16 px, лёгкая тень.
- **Карточки соцсетей как «сторис»:** картинка на всю карточку (3:4), название сети — белая «таблетка» в левом верхнем углу, в правом нижнем круглая кнопка со стрелкой ↗ (при hover заливается акцентом), при hover карточка слегка приподнимается, картинка чуть увеличивается.
- **Типографика:** шрифт Inter (самохостинг через `@fontsource-variable/inter`, без запросов к внешним серверам), заголовок врача крупный и жирный (800, отрицательный letter-spacing).
- **Кнопки:** полностью скруглённые («таблетки»); главная — залита акцентом, вторичная — с контурной рамкой.
- Ограничения прежние: без градиентов, цвета только из палитры и её производные, контраст по WCAG AA, `prefers-reduced-motion` учитывается.
